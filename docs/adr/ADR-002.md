### ADR D2 - REST frente a gRPC

**Estado:** Aceptado

**Contexto:** El sistema necesita conectar la interfaz pública expuesta a los usuarios con la comunicación interna entre los microservicios de Accesos y Sensores. Se requiere definir qué tecnología utilizar en cada capa considerando rendimiento, tipado y mantenibilidad.

**Alternativas consideradas:**

• Opción A: Utilizar REST/JSON de forma homogénea tanto para la API pública como para la comunicación interna entre microservicios.

• Opción B: Utilizar una arquitectura híbrida con REST/JSON para la API pública externa y gRPC (HTTP/2 + Protocol Buffers) para la comunicación privada entre microservicios.

**Decisión:** Se elige la Opción B.

**Justificación:** REST con JSON en la cara pública facilita la integración con clientes web y móviles por su compatibilidad universal y facilidad de depuración. En el canal interno, gRPC ofrece una serialización binaria más ligera, menor consumo de ancho de banda y multiplexación sobre HTTP/2, además de un contrato estricto mediante Protocol Buffers que previene errores de tipo.

**Costo aceptado:** Mayor complejidad en la canalización de construcción al requerir la compilación previa de archivos .proto dentro de los contenedores Docker, e imposibilidad de inspeccionar el tráfico interno con clientes HTTP convencionales sin herramientas gRPC dedicadas.

**Consecuencias:** Los clientes externos consumen la API de forma sencilla mediante endpoints REST tradicionales, mientras que el tráfico interno de la red de contenedores opera con alta eficiencia, baja latencia y un esquema de datos estrictamente validado.
